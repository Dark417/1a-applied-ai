- **背景**：现任 Anthropic Claude Code 核心成员、前 Google Chrome 工程总监 **Addy Osmani** 发了篇长文
  - 点破常见的 AI 编程误区：你大概率一直在「**过度提示**」（**Overprompting**）Claude
- **最扎心的事实**：Anthropic 官方把 **Claude Code 的系统提示词砍掉了 80%**
  - 结果模型代码跑分一点都没掉
- **问题所在**
  - 很多人还在用一两年前伺候老模型的那套「保姆式习惯」写 Prompt
  - 字数越堆越多
  - 面对 **Opus 5.5** 这代新模型，真正的高手都在做**减法**
- **1. 别教它怎么走，只给两件事**
  - 一句话说清「**终极目标是什么**」
  - 加上「**怎么验证做对了**」
  - 只要给它一个能跑出 **Pass/Fail** 的单测或判定脚本，它自己就能死磕闭环到底
  - 根本不用你寸步不离地盯着
- **2. 别迷信复杂的多 Agent 架构**
  - 很多人喜欢无脑堆 **Subagents**
  - Addy 直言：子智能体不仅不会让事情变聪明，还会让**延迟和账单成倍暴涨**
  - 从实测看，「**单个带 Skills 的 Agent**」在代码质量和性价比上往往完胜多 Agent 编排
- **3. 不知道怎么做，就让它反向面试你**
  - 需求不明确时，别硬憋 Prompt
  - 让 Claude 提问面试你，直到它能整理出一份完整的需求 **Spec**
  - 然后开个**新会话**，拿着这份 Spec 丢给它直接开工
- **4. 别当人肉代码扫描机**
  - 代码写完，先调一个**没看过聊天记录的独立 Agent** 去把 **Diff** 审一遍、改一轮
  - 把低级问题全甩给机器
  - 人类只留着精力，给核心业务风险做最终裁判
- **一句话总结**：模型每升级一代，最该做的第一件事不是拼命加规则，而是去提示词里「**删代码**」
  - 每隔几个月给 Prompt 瘦一次身
  - 别用伺候老模型的旧习惯，束缚新模型的发挥
- **Thread 补充**：作者附上自己前一天写的长文——别让自己成了 Agent 的拖油瓶
  - 虽然讲的是 Claude Code，但其他 Agent 也万变不离其宗
